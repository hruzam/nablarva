## The Research Question

> Can a living interactive agent be used as a deterministic callable cognitive process without collapsing it into SDK mode?

— Asymmetry, closing formulation

---

## Core Architecture (Agreed)

### The Inversion

The originating agent (Codex or Claude) does not inject into the other's terminal. Instead, it runs a **blocking shell command** that places a request, wakes the responder, and waits. From the caller's perspective, it ran one tool that took time and returned a reply. No external mutation of the caller's state.

### The Separation

**tmux carries the doorbell; files carry meaning.**

The wake mechanism (tmux send-keys, Agent View dispatch, or future equivalent) delivers only a signal — a request ID, nothing more. The actual task, constraints, context, and expected output live in a file the responder reads. The transport is decoupled from the content.

### The Transport

```
caller activates "consult colleague" (skill / AGENTS.md instruction)
  ↓
blocking script writes request into session folder
  ↓
script wakes responder (doorbell only)
  ↓
script blocks, waiting for completion signal
  ↓
responder reads request, works, writes response
  ↓
completion signal fires (commit, touch, or hook)
  ↓
blocking script returns response as stdout to caller
```

The caller never leaves its normal execution flow. The responder never leaves its normal reasoning loop. Neither agent needs protocol awareness beyond what the skill provides.

## Design Decisions

### Skill-Initiated, Not Hook-Triggered

The consultation is **agent-chosen, not lifecycle-forced**. The agent reads a skill that says "when you need architectural review, follow this protocol" and decides this is the moment. Hooks are wrong here — they fire on events regardless of intent. The skill carries discipline; the bundled script carries transport.

Both platforms support this: Claude Code via SKILL.md + `scripts/` + `allowed-tools`; Codex via SKILL.md + `scripts/` or AGENTS.md instruction pointing to a shell command.

### One File, Git-Tracked

Instead of separate request/response/signal files, a single markdown file per consultation. Both agents edit it in sequence. **Git tracks every touch.** The commit log is the conversation record. The diff is the review surface. The completion signal is the commit itself.

### Bounded Exchanges

Default: one-shot (request → response → done). Extended: 2–3 touches maximum, enforceable by the room script (refuse to commit past the bound). Theory, clarification, smoothed result — then close. No open-ended conversation.

### Session-Scoped Isolation

Each consultation gets a **temporary directory** with its own git repo, generated by the primer script. No pollution of project history. Access scoped to that session. Archive or delete on completion.

```
.agent-room/
├── sessions/
│   └── costa-20260807-143022/    ← git init here
│       └── consultation.md       ← single file, both agents edit
├── archive/
│   └── costa-20260807-131500.bundle
└── room.sh                       ← the primer/blocking script
```

### The `-p` Exclusion

`claude -p` is excluded from the design. Anthropic announced (then cancelled) a billing shift to third-party tokens for `-p` usage. Treat it as weather — it could return. Three alternatives, ranked:

1. **Agent View background dispatch** — `claude agents` can dispatch a headless session under subscription billing. Cleanest `-p` replacement. Vendor-coupled to Agent View.
2. **Interactive with initial prompt** — `claude "Read request at X..."` launches a fresh session, not `-p`. Under subscription. No context carry.
3. **Living session + tmux doorbell** — zero vendor dependency beyond "terminal exists." Most sovereign. Most brittle (active tool, permission dialog, unfinished input).

Recommendation: Option 1 for one-shot, Option 3 for held-on-line. The room protocol works identically under both — only the wake mechanism changes.

## Priority Sequence

### Probe A — One-Shot, No Hooks

Codex writes request file. Room script dispatches Claude (background session or fresh interactive). Claude reads, responds, script returns stdout to Codex. Tests the fundamental bridge.

### Probe B — Stop Hook Capture

Claude answers normally. Stop hook captures `last_assistant_message`, atomically writes response. Removes requirement that Claude explicitly operate protocol files. Tests reliable completion detection.

### Probe B-alt — Agent View Lifecycle

Same as Probe B but using `claude agents` background dispatch instead of tmux lifecycle management. tmux stays as human UX only.

### Probe C — Role Routing

Request header adds `role: architecture-observer`. The responder dispatches an appropriate subagent or routes to a dedicated session. Tests composition.

### Probe D — Multi-Round (Git)

Bounded 2–3 commit exchanges in the session-scoped git repo. Tests the git-as-conversation-medium pattern. The room script enforces the commit limit.

### Probe E — Reverse Direction

Claude initiates, Codex responds. Tests bidirectionality. Codex's `codex exec --json` or MCP-server mode may provide a cleaner return path than the symmetric design.

---

## Trust Tier

Agent-to-agent responses occupy a position in the sovereignty gradient that the current three-tier model (sovereign-authored, generated-but-committed, generated-and-gitignored) does not name explicitly. A separate protocol for the trust layer exists and will be tested under real conditions. The load-bearing question: whether a response that passes the trust protocol becomes **citable in a decisions file**, or whether it remains weather regardless.

---

## What Costa Is Not

- Not an orchestrator. It is a point-to-point bridge. One caller, one responder, one bounded exchange.
- Not a swarm. Topology is a line segment. Generalizing to a graph (fan-out, role-routing, multi-responder synthesis) is the domain of the multi-agent composition seed, not this one.
- Not a DSL. The protocol is plain files, plain git, plain shell. No custom language, no vendor-locked configuration format.

## Underlined: Post-Research Confirmation

_From Houston (Claude Code bonding layer) and Asymmetry (Codex bonding layer), 2026-08-05:_

- **Confirmed:** skills do not auto-dispatch scripts. Activation is model-judged. `!command` injection is the closest to deterministic pre-model execution, but the skill activation itself remains trust-based. Costa's design already assumes this correctly.
- **Confirmed:** neither platform has a `SkillActivated` lifecycle hook. Gating consultations (budget, rate-limit) requires hooking the tool call the skill uses (`PreToolUse` on `Bash` matching the room script), not the skill itself.
- **Confirmed:** Codex has a richer control plane than assumed — `codex exec --json`, app server (JSON-RPC), SDK, and MCP-server mode. The MCP-server surface means Claude Code could call Codex as a tool directly (no room script, no files). Cleanest one-shot path, but one-directional and vendor-coupled. Worth testing as Probe E alternative.
- **Confirmed:** Codex subagents are GA (6 concurrent), hooks are GA, `InterAgentCommunication` op type merged March 2026. The "never wake Codex" constraint from the original Asymmetry design is partially stale — Codex's hook surface may now support callbacks. Does not change the probe sequence; the blocking wrapper remains the safer first test.
- **Not confirmed:** whether Agent View background dispatch is billed differently from `-p`. Assumed same (subscription), but verify before depending on it.
- **Not confirmed:** whether Codex's app-server skill hot-reload and hook identity are stable enough for the room protocol to rely on them. Both researchers flag these as moving surfaces. Probe before building.
