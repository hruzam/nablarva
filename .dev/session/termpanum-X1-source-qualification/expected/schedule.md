# Frozen oracle specification and schedule

Scope: Q only; expectations are authored before capture and are not runtime results. Every case uses a fresh unique retained run bundle and private owned server/socket, 80x24, fixed executable and source binding; Q01 and Q10 require the identity, hashes, clock, argv, termios, coverage, process evidence, stderr, results and cleanup recorded in RUNBOOK. No fixture may emit before independent readiness/control acknowledgement. Each run retains failed, invalid and timed-out evidence, with no overwrite or retry substitution.

## Bytes and terminal state (Q02–Q04)

Each 1024-byte frame n is ASCII `F` + six zero-padded decimal digits + `:` (offsets 0–7), then offsets 8–16 hex `00 0d 0a 5c 1b 5b 33 31 6d`; for offsets i=17..1022 byte is ASCII `A` + ((n+i) mod 26); offset 1023 is LF. N=256 normal, N=4096 burst, frame numbers start at 0. This includes NUL, CR, LF, backslash and an ANSI escape; these are opaque payload, not semantic messages. For example frame 0 starts `46 30 30 30 30 30 30 3a 00 0d 0a 5c 1b 5b 33 31 6d 52`; the final byte is `0a`. Frame 1 begins `46 30 30 30 30 30 31 3a` and offset 17 is `53`. Frame 0 offset 10 is LF and 1023 is LF: under ONLCR these become `0d 0a`, while existing CR is retained. `wire.bin` and normal/burst wires are OPOST-off post-termios bytes. `cases/onlcr/wire.bin` is the 256-frame payload after each LF independently becomes CR LF with OPOST+ONLCR; configure remaining output flags so no other transformations occur and verify flags before and after; deviations invalidate, not pass. It is 262656 bytes versus 262144. Distinct split writes in ONLCR and OPOST-off: for frame 0 write byte ranges [0,12), [12,13), [13,14), [14,1024); this splits ESC and `[` and the SGR sequence; subsequent frames may be one write each. Payloads are constructed from the formula before transformation, not by reading a captured stream. Writes must handle partial writes and record actual release and completion separately. Chunks are not message boundaries.

Screen is a separate OPOST-off emission, hex `1b 5b 32 4a 1b 5b 48 41 6c 70 68 61 0d 0a 42 65 74 61`: erase, home, `Alpha`, CR LF, `Beta`. Reset 80x24 screen and cursor before emission. After completion, capture from that pane with explicit argv `capture-pane -p -S 0 -E 1 -t <bound-pane>` on the owned socket; no `-e`, `-N`, `-J`, `-a` or history request. Exact stdout is `Alpha\nBeta\n`, pinned in screen.txt. Screen capture is not binary fidelity evidence. Captured screen assumptions are hypotheses for witness/runtime, not proof of tmux behavior.

## Case matrix and bounds (Q04–Q09)

All counts below mean independent fresh invocations, except identity cases explicitly contain two incarnations inside one run. Each run has a 15 s monotonic watchdog; inability to establish progress/exit is timeout/unknown, not pass. Record actual fixed schedule and any lateness. Normal: 30 runs, 256 frames, deadlines 0,10,...,2550 ms measured from emission epoch; no catch-up claim if missed. Burst: 30 runs, 4096 frames without deliberate delays. Require exact byte equality and every frame once in order; capture start to ready metadata <=1500 ms, normal whole capture <=6 s, burst <=10 s. All 30 normal runs and the first of the 30 burst runs use the declared split on frame 0: these are within the existing populations, not extra runs. ONLCR: 10 normal workload runs using the same schedule and transformation; check exact wire and all frame boundaries in transformed stream. Screen: 10 independent short runs with exact screen and wire expectations. These ONLCR and screen counts are chosen Q coverage, not original numerical mandates. No invented threshold supersedes the original.

Normal timing: each of all 256 frames in each of the 30 normal runs is a marker, yielding 7680 samples. Independently record the monotonic timestamp immediately before issuing each frame's first write, and the timestamp after the reader completes an append through that frame's last byte to its readable file. Record both timestamps, run and frame number, and start and exclusive end byte offsets for every sample; OPOST-off frame n spans [1024*n, 1024*(n+1)). The same host monotonic clock is used, resolution and evidence recorded; the reader proves the matching byte offset using the file, not a frame-like terminal rendering. An append completing multiple frames supplies the same append-completion timestamp to each; a partial frame append is not that frame's visibility event. Latency = append-completion minus independent frame-release; retain all 7680 samples. Take the maximum of each run's 256 latencies, sort those 30 per-run maxima ascending, and require sample 29 (one-based) <=500 ms and the global maximum over all 7680 <=1000 ms. A missing or untrustworthy sample fails or invalidates its run and prevents a PASS; never omit it from the population. Actual emission and receipt times are not expected timestamps. Control evidence records actual write start/completion and independent acknowledgements; capture observations record receipt and must not backdate it. Capture duration is from collector start command to completed capture/exit, separately from marker latency.

False completion: 30 runs emit exactly `Done\r\nuser@host:~$ ` with OPOST off, then independently prove child alive and no further writes for 5 s on a monotonic control clock; only after the interval signal owned exit and obtain direct wait status. The words never imply completion, acceptance or turn end. Any absent independent proof yields unknown/incomplete, not semantic success. Normalized observation rules are in observations.ndjson; actual run IDs, PIDs, incarnation tokens, evidence paths and monotonic timestamps remain in retained records and must never be overwritten with frozen placeholders.

Ten runs per mode: sink loss after frame 2047 complete during burst; reader pause for 3 s beginning after frame 127 in normal; capture disconnect after frame 127 and reconnect before continuing with an explicit new bind; replay deletion of frame 127, duplication of frame 127, and swapping frames 127/128. The three replay wire files are exact mutated input; compare to unmutated normal oracle, which must reject each with a reason, never normalize mutations away. For live failures require incomplete/gap/error or documented measured narrowed coverage, never unqualified clean success. Measure direct supervised detection from independently observed injected loss to recorded detection <=1 s; for a paused reader where there is no directly supervised failure, report observed coverage and timeout independently, do not invent a detection timestamp. Bound every run by the watchdog.

Ten runs each: pane destroy/recreate with the same name/index in one owned server; fresh-server recreate with reused names/indexes; late attach after frame 127; disconnect/reconnect rebind as above. Late attach's ten-run count is chosen Q coverage, not an original numerical mandate; reconnect cases are the same Q07 runs, not an additional population. Require distinct proven process/server/pane incarnation or unknown, no inherited freshness, prefix absent for late attach, and explicit discontinuity until rebind. A new reader cannot change prior observation/receipt timestamps. Reuse is an attempted label reuse; if the implementation cannot force reuse, report that limitation, never assume same name proves same incarnation. Q09 requires comparator rejection, nonzero with a retained specific reason, for mismatched or incomplete bundles: in addition to the ten each Q07 damaged replay wires, take one retained healthy normal bundle, create a separate preserved copy that omits `capture.bin`, and submit that copy with all other original contents intact; it must reject nonzero with reason identifying the missing capture. Never modify the original bundle. Full twice-replay of every retained case and the ten-per-class stale/malformed/reuse rejection matrix belong to R's future qualification. Preserve unknowns for unsupported facts; no task_completed, accepted or turn-ended assertion may appear as true. Missing evidence is not an assertion of false.

Package boundaries: C heartbeat/health, R public inspect/replay/report timing, L view/lifecycle, E packaging and V shared admission are deferred; Q fixture comparison and fault replay remain mandatory.

Fault synchronization: before each selected boundary the fixture waits for a prearranged out-of-band barrier; after the selected frame write completes it acknowledges the boundary and waits for an independent continue signal. The controller then performs the specified owned action, records its monotonic completion and continues emission. This intentional barrier applies only to fault/coverage cases, never the healthy unpaced burst or paced normal populations. For reader pause, record pause completion, continue emission, then independently resume after 3 s. For disconnect, record detach and resume only after reconnect/bind outcome; declare the entire interval between detach and proven rebind uncovered. For late attach emit frames 0..127 before attachment, then attach and prove readiness before continuing 128..255. For replay mutation the source data is the specified mutated file and the reference remains the unchanged normal file. Directly supervised detection is measured from the independently witnessed action to the Q observer's explicit failure/coverage detection, not to the controller's own action acknowledgement. Where no failure can be directly established (e.g., pause merely delays a healthy reader), detection latency is not applicable and a measured coverage result is still required.
