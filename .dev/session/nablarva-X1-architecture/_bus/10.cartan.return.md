## Verdict — REVISE

The source/deploy separation fixes the real collision: reposoma cannot have its own project `.germline` while its same directory is the global target. **Single weakest assumption:** a normal rsync leg is safe during the first deploy. Today `~/.germline` is a symlink to `~/reposoma/.germline` (local `ls -ld`, 2026-10-12). `ensure_dir` treats that symlink as an existing directory, and `rsync ... "$HOME/.germline/"` can follow the destination path and write into reposoma. **Primary risk:** the first “global deploy” silently changes the old source/project layer and leaves the migration apparently complete.

**Alternative:** keep the proposed real-directory target, but make `deploy_germline()` fail closed on `-L "$HOME/.germline"` in both dry and live modes. The operator first verifies the link target, saves/commits the old source, unlinks that exact symlink, then runs the reviewed deploy to a real directory. Refuse an unexpected pre-existing real tree until its differences are reviewed or backed up. Never let the deploy script remove the old link for the operator, and never use `rm -r` on it. Full deploy should run the germline leg before wrappers that read it; document that `--codex-only` alone does not refresh this dependency (or explicitly include it and change that flag's scope).
