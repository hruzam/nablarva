## 6. Disconfirming evidence

### 6a. Against the September hypothesis ("none of these reads session state off the screen; they read on-disk records or hooks and use tmux only to type")

Inside the nine September leads:
- clibot: polling mode reads the screen ("periodic tmux capture when output becomes stable", row 1). The hypothesis holds only for hook/ACP modes.
- codex-wake: before a tmux paste it inspects a bounded pane region for approval prompts or running tools (row 3), i.e. it reads the screen as a safety guard, while using app-server thread status where it can.
- Held: codex_monitor_skill (rollout), claude-peers (channels), interlink (socket, queue), agy-acp (conversation DB; PTY "never parsed"), codex-agent (rollout, archived). Not verified: cc-multi-cli-plugin.

Outside the leads, published tools that DO classify from pane content, most with 2026 commits:
- muxray (pushed 2026-09-22), agenmux/snirt (2026-11-24, "no hooks"), codely (reads last few pane lines), bosun-tmux, kiosk-core, tmuxcc, tmux-overmind (daemon scraping each second; repo path 404 on API check, so existence/date unverified), CCB `$ccb_diagnose`.
- Hybrids: samleeney and accessd use hooks; marmonitor uses disk files + CPU; CCB mixes hooks, session logs, pane states.
- agent-manager (710 stars) and Herdr (52.9k stars): mechanism not stated on the pages read; Herdr is named as an OSC 7501 consumer in a forum thread (unverified).
So the practice is mixed. Hooks/disk are common for Claude and Codex; screen parsing is the norm for tools that want zero setup or many CLIs.

Also against "tmux only to type": the typing itself is a state-bearing act (row 44: send lands on a human draft; row 40 CCB checks the input box before paste).

### 6b. Against a PTY layer being stable

- TUI change broke a pane parser: Claudlobby #838 (2026-07-28): "esc to interrupt" no longer matches current Claude Code build (row 48). Bosun's fixtures pinned to Claude Code v2.1.152 (row 28).
- Scraper false positives from scrollback (row 49); codely test shows "error: command not found" classed as executing (row 33).
- Delivery failures: Codex leaves multiline tmux sends unsubmitted (rows 42, 43 with "delivery still reports success"); Claude Code swallows Enter as newline for long prompts (row 45); newline splitting of short multiline nudges (row 46); half-typed draft collision (row 44); CCB self-documented non-atomic paste/Enter, Ctrl-C deadline clearing (row 40). Mitigation reported in four independent repos (rows 42, 45, 46, 47): one bracketed paste then a single Enter.
- Claude Code's own OSC 7501 does not work inside tmux (row 17); `CLAUDE_CODE_DISABLE_TERMINAL_TITLE` disables it.
- Claude doc: collapsed paste placeholder for >800 chars or >3 lines (terminal-config page): a pasted pointer longer than that is stored and shown as `[Pasted text #N ...]`, sent in full on submit (documented behaviour, not a bug report).

### 6c. FOR a PTY layer (vendor doors failing, flagged, withdrawn, or delivering silently)

- Claude channels remain research preview with allowlist, `--dangerously-load-development-channels`, auth limits, and a stated risk that the contract may change; the doc also says a channel server negotiating protocol revision 2026-07-28 is not registered on the v2 MCP client runtime (row 10). claude-peers depends on the dev flag (row 5).
- Claude cross-session messaging can be silently disabled (telemetry/flag-evaluation env vars), headless `-p` workers drop held messages, bypass-mode receivers hold messages for approval; 2.1.328-2.1.332 shows state-surface bugs still being fixed (rows 16, 19).
- Claude agent view: not for sessions in other terminals until backgrounded; preview; on-disk state "not a stable interface" (row 14).
- Codex: `codex queue` message stays `accepted` with no delivery confirmation (row 4); no ack/response channel (row 11); app-server WebSocket "experimental and unsupported", app-server auth "never permitted for commercial or hosted services"; `PermissionRequest` hook cannot `ask`; hooks must be trusted (rows 20, 21). Docs/README disagree whether hooks are experimental.
- tacogips/codex-agent (rollout reader) archived 2026-11-14 with no reason stated (row 9).
- agy: OSC 7501 requires a supporting terminal; no documented inject door for a running TUI; third-party agy-acp adapter's premise overtaken by native ACP (rows 8, 12, 24).
- Vendor state surfaces are not uniform: marmonitor notes Codex and Gemini do not report `permission` from files (row 35).
