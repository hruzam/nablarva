## 2. One operator scenario and adopt/build decision

**Scenario S1 — inspect a quiet fixture without declaring it done.** On office, an operator selects one expressly created synthetic process in one pane of a private tmux server. It emits numbered output, ANSI redraws and completion-like text, becomes quiet while still alive, then exits on its own schedule. The question is whether capture covers the declared interval and which facts actually establish source health and process exit. The answer is a retained capture, comparison report and conservative local observations. No vendor CLI, network, credentials or living collaborator is involved.

The **first successor is documentary preparation for S1**, not S1 execution. The first runnable observation slice is package Q after its release. Its human surface is an inspectable report; no live view is required to qualify bytes. Package L later supplies htop-like use beside Nablarva by reading the same machine evidence and health projection. It never becomes the store or changes source lifetime.

## 4. Planned qualification and acceptance evidence

**Everything in this section is planned.** Proposed local thresholds below are fixed for the first released Q/C/R/L/E runs; Majkee may change them before execution by recording the replacement and reason. Failed runs retain their original thresholds. They are not Composer parser numbers, Termbrana M2 bars or animal-wide protocol commitments.

**Independent oracles and boundaries.** The oracle author is independent of the collector implementation. Before collector work, the head/fresh verifier checks the expected corpus, schedule and hand calculations/reference-generation specification, then pins hashes. Byte assertions compare the expected **PTY-master stream after declared slave line discipline**, not helper `write()` payload against different output processing. Use one known configuration with `OPOST` off, plus a separate deliberate `OPOST|ONLCR` case expecting NL→CR-NL. Record `tcgetattr` flags/control characters immediately before/after emission, terminal size, helper/payload hashes and actual tmux binary/tag. Any unexpected termios change invalidates the run rather than indicting tmux. Rendered assertions use a separately authored `screen.txt` at fixed 80×24 with fixed capture options; they never substitute for byte expectations. Fixture control acknowledgements, monotonic emission times and direct child wait status are independent of captured text; no typing or injection is needed.

**Workloads and measurement.** One pane, one private server/socket, office host. Normal case: 256 numbered 1,024-byte frames, one every 10 ms (256 KiB), with frozen CR/LF, NUL/backslash and ANSI/split-sequence subcases. Burst: 4,096 frames of 1,024 bytes (4 MiB), no deliberate pacing. Rendered subcase is a short separately frozen screen sequence, not the binary burst. Run each healthy workload 30 times from a new process invocation; sort each metric and use sample 29/30 as p95, report maximum and every run. Record host/kernel, binary versions/hashes, source boundary, dimensions, entry argv/environment allowlist and load context. Never dump the environment or copy secrets.

| Planned case / package | Independently specified expectation and proposed bound |
|---|---|
| Healthy source fidelity / Q,C | Within declared start/end interval: exact byte equality, zero missing/duplicate/reordered numbered frames for all 30 normal and 30 burst runs. Log chunking without treating writes/chunks as messages. A collector sequence proves receipt ordering only, not loss before observation. Late attachment labels pre-attachment coverage absent. |
| Latency and invocation / Q,C,R,E | Same-host monotonic clock: independent helper release of each marker → completed reader-visible file append, including source/collector/flush overhead: p95 ≤500 ms, maximum ≤1,000 ms on normal workload. Full finite `inspect`/`replay`/`report` invocation: fresh `zsh -f` process start → exit plus readable complete result file, including proposed entry, interpreter/imports, parse and output: p95 ≤1,500 ms, maximum ≤3,000 ms for 256 KiB, 30 invocations each. Capture process start → bound source/ready metadata ≤1,500 ms; normal whole capture ≤6 s, burst ≤10 s; watchdog 15 s. Measure final packaged entry again at E, not a preloaded function alone. |
| Quiet/false completion / Q,C,L | Emit fake `Done` and prompt-looking paint, then remain alive without output for 5 s before a separately timed exit. All 30 runs must report quiet/known-alive subject where independently proved, never `task_completed`, `accepted` or “turn ended.” Unknown semantic state remains unknown. Pane EOF/close is not the helper's exit status or task outcome. |
| Observer health/staleness / C,L | Collector heartbeat every 250 ms, separate from data arrival. Close/reopen view ten times: no source/collector termination, input, resize or selection-following into a new incarnation. Two views are readers only; their heartbeats cannot make collector health fresh. |

Runtime artifact shape is **local proposed test/product data**, not an animal-wide schema: one immutable `manifest.json` (identities, versions, clocks, termios, expected hashes and coverage), `capture.bin`, collector `records.ndjson`, independent `fixture-control.ndjson`, atomic `health.json`, and `comparison.json`/`report.md`. No shared `vist.*` event or approved four-state vocabulary is introduced. The first D packet specifies this contract in prose and freezes no API.

Retain each run in a unique directory, including failing/invalid/timed-out runs, expected hashes, exact argv, stderr and the original criteria; never overwrite a failed run with a retry. Fixture corpora contain synthetic nonsecret data. Future real data stay host-local under an approved retention/redaction policy; no committed real transcript or raw history is required. If criteria fail, record REVISE/REFUSE or an explicitly narrowed supported scope; no near-miss PASS or threshold change after seeing results.
