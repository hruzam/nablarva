Source: Majkee's buffered input, subsequent Cartan proposal and acceptance in this
conversation, 2026-11-10. This is a task brief, not a new lock.

## Problem and accepted proposal

Growing organ-specific session history makes relevant evidence difficult to find.
Folder prefixes alone miss relationships: Termbrana includes `composer-01-parse`
and historical `toolbox-termbrana-*` beds. Discovery must support organ-scoped
consultations and orphan checks without routinely reading every historical artifact.

Start with one Termbrana pilot. Use the existing project/organ entries and the open
Boost reader concept. Trace membership through affected contracts and dependencies;
allow cross-organ membership and expose unclassified candidates. Maintain navigation
relationships once and derive additional views when warranted. Preserve exact paths
and commit pins for historical evidence.

Investigate reusable bounded Luna/max crawl workers, at most Terra for difficult
cases. Findings go to the owning head; Houston handles explicitly invoked bounded
architectural consultations. Newer evidence gets inspected first, but never gains
authority merely through age or placement under `.dev/`.

## Laravel Boost analogy

Official source: https://laravel.com/framework/docs/boost (read 2026-11-10).
Useful principles: compact initial guidance, focused on-demand skills, explicit rule
applicability, installed-package-aware documentation retrieval and reproducible resource
updates. Boost updates its own resources; it does not establish automatic reconciliation
of arbitrary project documents or newest-wins authority. Nablarva's reader remains an
open local concept, already pinned by `docs/ARCHITECTURE.md:496`.

## Pilot and open threads

Agree lookup questions, freeze source provenance, enumerate relevant beds with reasons,
classify lifecycle/authority and report discrepancies. A second reader repeats the same
questions with the same sources. Compare misses, mistaken authority and reading effort.
