# The goals in plain words — context, what it buys, cost, consequences

"Needs you" says what only Majkee can give. Goals with nothing there can run inside the team.

## G0 — umbrella (your sentence, proposed)
- **Context:** you wrote it as an edit of the X0 RUNBOOK's goal line — find out what the accepted home trial can support for the relay organ, and qualify observations, before any implementation or transport is chosen. I proposed it as this bed's umbrella.
- **Buys:** one yardstick. Every other goal must serve this question or be dropped.
- **Cost:** none.
- **Consequences:** it ends only by your word. No goal here picks a mechanism.
- **Needs you:** yes or no — is this sentence the umbrella of this bed.

## G1 — the party is bound
- **Context:** a poke is allowed only when the receiver, the door, the return path and the bell are written first. Ids go stale whenever a window is rebuilt, and every pane here falls back to a shell if its agent exits.
- **Buys:** messages land in the right seat, and each seat has said itself what its tools can reach.
- **Cost:** small. One roster, one confirmation per seat, re-read after any rebuild.
- **Consequences:** without it a typed line can land in a shell or in the wrong agent. It runs on the coordination permission you gave and covers nothing beyond pokes, bells and the controller's push.

## G2 — the export is checked by a non-author
- **Context:** I summarised the 45 files of the VIST X0 bed alone. Cartan checked the first revision; I repaired fourteen points.
- **Buys:** a checked map, so the next session does not re-read the pile.
- **Cost:** one cycle paid, plus one small re-check of my repairs, because repaired bytes are new bytes.
- **Consequences:** it is still a summary. Where it matters, the origin file wins; if the origin changes, the export is stale.

## G3 — which door candidates exist today (reading only)
- **Context:** every recorded result is from older CLI versions. The trial once spent three cycles on keystroke guards while a native door already existed.
- **Buys:** one table per direction of every candidate found in help texts, vendor documentation, local session files and the records — with the interface, what it needs, the old evidence, and what a live try would still have to show.
- **Cost:** one seat, about one cycle of reading. No release.
- **Consequences:** it feeds G8 (what to probe) and G10 (which door per seat). It will also put lock L14 D1 on your desk with evidence, because it lists the vendor doors that lock parks. Listing is not adopting.

## G4 — U01: one real unknown screen, or "missing"
- **Context:** the trial never met a genuinely unknown native screen, so "unknown stays unknown" was never tested.
- **Buys:** either one real fixture, which makes U01 testable, or an honest "none exists in the history", which means U01 needs a new capture and a different release.
- **Cost:** opening old captures that hold private screen content, and two seats (the labeller must not be the selector).
- **Consequences:** this is also the X0 packet's own first operation. If you accept that packet without naming a bed, two beds could run the same search and record two different results.
- **Needs you:** name the one bed that executes U01, and the scope — which captures may be opened and how they are redacted.

## G5 — U03–U06: one candidate receiver contract
- **Context:** expired request, wrong recipient, pointer-is-not-authority, hop and retry limits. All four test one thing: how the receiver decides.
- **Buys:** one written contract and one oracle sheet instead of four projects. Later tests become possible.
- **Cost:** one author and one non-author review, on paper only. The risk is designing ahead of observation; the X0 authors put observation first.
- **Consequences:** it stays a candidate. Without it U03–U06 cannot be tested at all.
- **Needs you:** nothing to draft it. Adopting it is yours.

## G6 — U02: the receiver exits between the text and Enter
- **Context:** real on today's panes: text typed after an agent exits lands in a shell.
- **Buys:** evidence whether a two-step carrier can refuse, or keep the attempt uncertain, safely.
- **Cost:** the highest of all goals — starting a disposable sample, one attempted delivery into it, killing its process, an independent witness, and building a two-step actuator if none is eligible.
- **Consequences:** `codex queue` cannot answer it. It is the case that tests the L14 D1 base layer most directly.
- **Needs you:** name the executing bed, and a release for each of those actions.

## G7 — retire the provisional file-poke
- **Context:** file-poke is a bridge with a written duty: the bed that uses it must retire it once a real mechanism is qualified.
- **Buys:** the debt closed properly, with a tombstone instead of a silent rewrite.
- **Cost:** nothing now. It is blocked until a replacement exists.
- **Consequences:** last by nature. Until then it is reviewed at each gate closure.
- **Needs you:** three separate words — what the replacement covers, adoption of that transport, retirement of the chapter.

## G8 — live door probes on samples
- **Context:** forked from G3. A door on a list is a candidate, not a route.
- **Buys:** one controlled try per door on today's versions, recorded per layer: carrier result, native turn, receipt.
- **Cost:** starting sample sessions (trust dialogs are your hand), real sends, an independent observer. The auditor seat fits that role.
- **Consequences:** the first goal that activates and delivers in the sense of L21. Its results feed your later choice of mechanism. It adopts no door.
- **Needs you:** a release naming the samples, who sends, and the side effects.

## G9 — evidence custody and the clean-table hand-over
- **Context:** the eight C04 inputs the X0 packet pins sit in `/tmp` on home, which is memory-backed. The host has been up since 2026-09-29; one reboot erases them.
- **Buys:** (a) the evidence survives, or is let go knowingly; (b) the next session starts from one card.
- **Cost:** (a) a few minutes to copy private captures to a durable host-local place, never into Git — or accepting the loss.
- **Consequences:** if a reboot comes first, the packet's hashes can never be re-checked and the C04 reading cannot be repeated.
- **Needs you:** copy, or let go.

## G10 — a vendor-neutral friendly reminder (your question)
- **Context:** an open cycle looks the same whether the seat works, waits on a dialog, ran out of context or is gone. The shared file-poke chapter already describes a finite check-in for this; the goal turns it into a script.
- **Buys:** stage 1 — the one who waits gets one printed outcome per cycle: closed, a return waits for review, or still outstanding. Stage 2 — the silent seat gets one reminder.
- **Cost:** stage 1 is a script of about 60 lines plus one tmux option that you set. Stage 2 is a second send: a release, and never after an uncertain first send.
- **Consequences:** it would be the first small product of the relay line. A timeout says only "outstanding when checked", never "the seat is dead".
- **Needs you:** go or no-go on stage 1, where the script lives, and whether it may use any output beyond a printed line and a file note.
