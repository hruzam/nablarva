# G10 — a vendor-neutral "friendly reminder" when a seat is asleep

**Why:** a POINT without a RETURN looks the same whether the seat is working, stuck on a dialog, out of context or gone.
Today the waiting owner polls by hand. Majkee asked for a small, vendor-neutral helper with a timer.

**Two stages, on purpose**

- **Stage 1 — watch and tell the one who waits.** A finite script: given a RETURN path and a deadline, it ends when the file is
  complete or the deadline passes, and then tells the *waiting owner* (one printed line, a desktop notification, or one line into the
  owner's own pane). It sends nothing to the silent seat. This is observation only (L20).
- **Stage 2 — remind the silent seat.** One extra pointer to the same POINT through that seat's door. This is a second send, so it
  is delivery (L21) and it bends the file-poke rule "once, never after an uncertain send".

**Parts that already exist (nothing vendor-specific)**

- tmux `monitor-silence <seconds>` flags a window that printed nothing for that long. No script. Setting it is Majkee's hand.
- A deadline on a file: `timeout` + a poll loop or `inotifywait`. A one-shot timer: `systemd-run --user --on-active=<time>`.
- Ancestor in the archive: `vist-heartbeat.py` — one bounded wake under a lease (expiry, max wakes, pending id), started only by
  an external timer. Evidence, not a live tool; its guards are the right ones to copy.

**Edge cases the design must answer**

1. Busy is not asleep: a reminder into a working seat is noise and queues behind its turn.
2. The first poke was uncertain: a reminder may deliver twice, so its line must be harmless when repeated (same POINT, same id).
3. The seat is gone: panes are shell-rooted, so text would land in a shell. Look first, or do not send.
4. A dialog is on screen: Enter would answer it. Never send into a dialog.
5. The RETURN exists but is half written: check for the last heading, not for the file.
6. Two watchers on one POINT: one lock file per POINT.
7. The watcher dies: it is finite and leaves a line when it ends; nobody watches a daemon.
8. Count: at most one reminder per POINT, then the human is told.

**Done when (stage 1):** one script under about 60 lines, no daemon, with the lock and the completeness check; tried on one real
POINT of this bed; a non-author read it. **Stage 2** is only specified here, not built.

**Bounds:** no daemon, no resolver, no envelope, no generic launcher. No tmux option is changed by the script.

**Open questions:** where the script lives (bed-local, or the session-window line in ia-sync); whether telling the owner goes
through the owner's pane or a desktop notification.
