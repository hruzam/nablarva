# G3 — which door works per direction on today's versions

**Why:** every recorded result is from older CLI versions (export §6). The weak direction is into Claude. Before anything is built,
one seat should list and try the doors that already exist.

**Done when** — on home, on the installed versions (today codex-cli 0.171.0, Claude Code 2.1.330), for each direction
(Claude→Codex, Codex→Claude, Claude→Claude, Codex→Codex):
- one named door is tried **once**: POINT with a random nonce written first, one carrier call logged with UTC before/after and exit code;
- the result is recorded per layer: carrier result · native turn seen · receipt with matching nonce;
- a door that cannot be tried is listed NOT RUN with the reason;
- the state probes are recorded beside it (`~/.claude/sessions/<pid>.json`, `claude agents --json`, Codex `read_thread`).

**Bounds:** disposable sample receivers only, never the party's working panes. At most one message per door per direction. No retry
after an uncertain result. No `--resume`. The archived adapter code is not reactivated. **No door is adopted** by this goal.
