## 3. Technical rules I would hand you first

1. **The carrier Bash is a whitelist.** `cat`, `grep`, `ls`, `git status/log/diff/add/commit` and `sed -n` work. `cp`, `od`, `unzip`, `git apply` and `for` loops are blocked: spawn delta. Never route around a denial.
2. **The Write tool strips trailing whitespace.** Never hand-write a unified diff; generate it with `git diff --no-index` from an edited scratch copy.
3. **Land every majkee message verbatim** in `raw/answers.majkee.<topic>.<date>.md` before acting, with your reading below it tagged `inferred: oraculum`. A TUI prompt suggestion is never his word.
4. **Every time you record comes from `date` in the same turn.** Record a relay, send or commit only after it happened. (I broke this six times across two sessions.)
5. **A commit message may cite only files that are in that commit or in an earlier one.** Check with `git cat-file -e <sha>:<path>`.
6. **A change log is a claim.** Diff the bytes before forwarding a "narrow" revision.
7. **Write your own expected list before reading a drafter's revision**, then compare. It costs nothing and is real independence.
8. **Shared files with other heads' uncommitted lines:** stage only yours by building the index blob (`git hash-object -w` + `git update-index --cacheinfo`), via delta.
9. **Before pruning a bed, grep the other repos and live configs for its path.** X1 held a preamble that two live vaults in ia-sync still read.
10. **A `locked: L<n>` tag never reaches past that lock's text.** Name-locks are not ownership. Deaths are not reopened by qualification. This was the dominant defect class: eleven instances in one sitting.

## 6. Method: the costed decision deck (said: majkee 2026-10-24 "looking fine like methodologic substrate for next cSharp (for runbook handoff)")

Use it for any decision that is the operator's. It is not a lock and not a mandatory gate. It extends the for-myShell gavel line from therapy S11. The working example is the R9 deck, at `nablarva@519a211:.dev/session/nablarva-X3-architecture-sitting/raw/gavels.R9.oraculum.2026-10-22.md`.

```
GAVEL <source-qualified id, e.g. R9-2a> · <the question, one sentence?>
  options:      a) …  b) …  c) …
  context:      <full sentences; enough to decide without opening any file>
  buys:         <per option: what it gets him>
  cost:         <per option: time · his hands · risk>
  can be lost:  <per option: what disappears or gets harder>
  consequence:  <per option: what follows, what it closes, what it opens>
  lean:         <seat> → <option> — <one-sentence reason>
  source:       <path[:line] — for verification only, never the only carrier of meaning>
  answer:       ___
```

How it ran well:
- One block at a time, in chat, with the whole deck also in a file he can read alone.
- His answer lands verbatim in `raw/answers.majkee.*` before anything acts on it.
- Keep ids source-qualified (never restart G1–G9-style numbering).
- When his answer is "own" or mixed ("b|c" + notes), stop. Build a placement table of his notes, ask the few questions only he can answer (A/B/C), then relay.
- Split document approval from lock adoption: each lock is its own block. A proposal with two readings comes back as explicit alternatives (P5-a / P5-b), never as one block that hides the choice.
