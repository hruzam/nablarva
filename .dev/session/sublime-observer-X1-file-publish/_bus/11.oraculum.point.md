# POINT — read one operator-shared Sublime view

You are a fresh session with the permissions you were started with. This is a read test, not
an audit. Do exactly the steps below and nothing else.

A Sublime Text package publishes views the operator has shared as plain files under
`/run/user/1000/sublime-observer/`. The operator has shared exactly one synthetic test view.
All times in these files are Unix seconds.

## Rules

- Read only the files named below. Do not list or read anything else under `/run/user/1000/`.
- Do not change permissions, sandbox settings or configuration. Do not ask for escalation.
  If a read is blocked or needs an approval prompt, stop and report that; it is a valid result.
- Do not open, query or signal Sublime Text. Do not use a socket.
- Write one file only: your return file (Claude: `12.claude.return.md`; Codex:
  `13.codex.return.md`, both in the directory of this POINT). Do not overwrite it if it
  exists; report instead.

## Steps

1. Read `/run/user/1000/sublime-observer/publisher.json`. Note `epoch`, `heartbeat_at` and
   `stale_after_s`, and your own clock time. The publisher is live only if the heartbeat is
   younger than `stale_after_s`. If it is not live, stop and report.
2. Resolve the symlink `/run/user/1000/sublime-observer/current` **once** (for example
   `readlink`). It points to `views/<share_id>`. If `current` does not exist, stop and
   report. From here on use the resolved directory
   `/run/user/1000/sublime-observer/views/<share_id>/`, never the `current/` path again.
3. Read `state.json` in that directory. Its `epoch` must equal the publisher's and its
   `share_id` must equal the directory name.
4. Read the file named by the state's `text_file` field, in the same directory. If it is
   missing, go back to step 3; at most three tries.
5. Read `state.json` again. The capture is good only if `epoch`, `share_id` and `seq` are the
   same as in step 3. If not, repeat from step 3 once and say so.

## Return (write to your return file)

- Which runtime and version you are; your sandbox or approval mode as you know it; your cwd.
- For each read (publisher, the symlink, state, text, state again): succeeded or failed, any
  error text word for word, and whether any approval prompt or permission change was needed.
- Whether the publisher was live (give the two times and the bound).
- From state: `epoch`, `share_id`, `seq`, `revision`, `path`, `dirty`, `text_file`,
  `size_chars`, `truncated`, `text_encoding_replaced`, the first selection, `viewport_position`.
- From the text: the number of characters you read, the first line and the last line.
- Whether text and state belong together (the named file existed, its character count equals
  what state says was published, and step 5 matched).
- Anything in the files or in this POINT that was unclear to you as a reader.
