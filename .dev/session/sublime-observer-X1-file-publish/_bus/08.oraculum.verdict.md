# VERDICT — audit of contract and implementation

The audit is accepted as sound work: hashes match, 74 tests ran, findings are source traces
with line references. Its closing opinion, "not sound for the stated gate until the
concurrency and revocation conditions are resolved or explicitly accepted", is accepted.
Findings 1 to 3 touch two clauses of the gate itself ("a consistent text-and-state capture";
"no capture presented as current"). None of them occurred in the witness; all are reachable.

The head designed this contract, so this disposition is not a verification. Fixes go to
trajectory, then assay, then a short re-audit of the diff by Codex.

## Disposition

| # | Audit rank | Head | Decision |
|---|---|---|---|
| 1 | major — stale takeover does not fence the old writer; two starts can both pass | agree; the head's earlier lean ("keep takeover of a stale live pid") was wrong | **Fix.** Ownership by a kernel lock: the publisher holds an exclusive non-blocking `flock` on a lock file in the root for its whole life. Lock not obtained → do not publish, say so in the console. The kernel releases it on any death, so the stale-pid and heartbeat-age takeover logic is removed, not extended. Residue cleanup happens only after the lock is held. |
| 2 | major — `current` can pair share A's state with share B's text | agree; plausible in practice because unedited shares all use `text.0` | **Fix, both sides.** Publisher: text file names carry the share id (`text.<share_id>.<revision>` or equivalent), so a switched `current` yields a missing file and a retry, never a wrong pairing. Contract: the reader resolves `current` once and reads state and text from that one directory; state names its `share_id`. |
| 3 | major — unshare and path refusal are queued behind earlier captures and fail open on cleanup errors | agree on fail-open and on the save-as window; the queue delay itself was one sample (under 100 ms) in the witness | **Fix.** Unshare and close discard that share's pending captures before removal. If removal fails, the publisher stops publishing and stops its heartbeat (readers then see "not live") and reports in the console. The sealed-path check runs synchronously on save and on path change; a newly sealed path revokes at once. |
| 4 | major — update block can overwrite through a hard link; ancestors may be symlinks | agree on mechanism; rank **minor** here: it needs a hard link planted inside the operator's own package folder | **Fix, cheap.** Update writes fresh inodes (`cp --remove-destination`). Symlinked ancestors of `Packages/` — state in the task text; do not build ancestry checks. |
| 5 | minor — liveness check is not a lease over the read | agree; inherent to plain files | **Document** in the contract: a capture is valid at the checked instant; read state again after the text and compare epoch, share id and seq. No code. |
| 6 | minor — path refusal is lexical with best-effort resolution | agree | **Small fix:** a path whose resolution raises is refused (fail closed). Everything else (case, hard links, untitled buffers, wider lists) → the security sibling on the ledger; stated as a limit. |
| 7 | minor — index and `current` have intermediate states | agree | **Small fix:** when a second share is added, remove `current` before the index is replaced. Remaining intermediate states are documented; finding 2's fix makes them harmless to a reader. |
| 8 | minor — `errors='replace'` can alter text silently | agree | **Small fix:** state carries a flag when replacement occurred. |
| 9 | minor — install claims stronger than guards | agree | **Text fix** in the task at closure: an interrupted install can leave staging; ownership is by the five names only; the runtime `rm -r` is the operator's judgment. |
| 10 | note — runtime directory safety assumes same-user trust | agree | **Document** as the trust boundary. No pinned directory handles in X1. |
| 11 | note — editor effects are bounded evidence | agree; matches Oraculum·Codex (05) and both assay verdicts | **Document.** Gate claim stays the bounded sentence. No large-buffer measurement in X1; stated as not shown. |

Missing tests named by the audit are adopted as the acceptance tests of the fix round:
simultaneous start and resumed old owner; `current` switch between state and text with equal
revisions and distinct bodies; queued publish then unshare with injected removal failure;
hard-linked destination in the update block.

## Consequences

- The payload changes (`contract.py`, `publisher.py`, possibly the settings). The installed
  copy on home becomes stale; the task version is bumped; majkee reinstalls by the update path.
- Witness evidence that survives a code change: install and removal mechanics, live load and
  unload, plugin host, sandbox reads by path. Evidence that must be shown again for the new
  code: publish, unshare, quit, crash, one fresh read — by unit tests and the disposable trial,
  plus a short real-editor smoke by majkee (about five minutes).
- Reader instructions change (`_bus/01` wording, README contract): resolve `current` once.
