## Findings

1. **Major — takeover does not fence the old writer.** `contract.py:312–331, 336–341, 343–386`; `publisher.py:310–314`. A live process with a heartbeat older than the bound is treated as residue; once the new store starts, the old process can resume and replace `publisher.json` with its own fresh epoch and continue writing into the new tree. Two simultaneous starts can also both pass the check before either creates its publisher file. Consequently a fresh heartbeat can identify the wrong writer and the one-publisher and crash/restart guarantees do not hold under these interleavings. **Observed** in control flow; no concurrent process experiment. Direction: atomic exclusive ownership and fencing for every subsequent write, including stale takeover.

2. **Major — `current` can mix two shares in a rule-following read.** `contract.py:388–398, 442–443`; `tests/reader.py:37–54, 58–66`. A reader opens `current/state.json` for A, then A is unshared while B remains; `current` switches to B before the reader opens `current/text.<revision>`. If B has the same revision filename, the reader returns A's state with B's text; both have the same epoch, so the test reader's epoch check passes. **Observed** in path resolution and interleaving. Direction: pin the share directory or immutable share ID across the entire read and validate it.

3. **Major — unshare and path refusal are asynchronous and fail open on writer errors.** `publisher.py:208–220, 240–265`; `contract.py:489–522, 388–398`. Unshare removes the marker immediately, but earlier queued captures are written before queued cleanup; if removal fails, the writer logs and continues heartbeating, leaving that capture presented as current indefinitely. Save-as into a sealed path is detected only at a subsequent debounced publish or poll, so the previous share remains visible in that window; queued captures taken before detection can also still publish. **Observed** in ordering; actual I/O failure and editor event timing not exercised. Direction: make revocation invalidate pending work and fail closed on cleanup failure, with an honest completion boundary.

4. **Major — an install update can overwrite a hard-linked unrelated file.** `install-pkgs/sublime-observer.md:123–138`. The five destination names are checked for symlinks and regular-file status, but a regular destination can be a hard link to another same-filesystem file; `cp` truncates and overwrites the shared inode. The parent `Packages` and its ancestors may also be symlinks because only the final package path is checked. **Observed** in shell semantics and guards; no install executed. Direction: replace verified files using fresh staged inodes and validate destination ancestry/ownership, with explicit treatment of concurrent changes.

5. **Minor — heartbeat and snapshot are not a transactional liveness check.** `tests/reader.py:25–34, 58–66`; `contract.py:181–191, 400–412`. A reader can check a fresh heartbeat, pause past the stale bound or across unshare/shutdown, then finish reading already-open files and report an old pair. During shutdown `publisher.json` is removed last, so absolute paths can also succeed while cleanup is in progress. Atomic renames give coherent individual files, not a lease over a read. **Observed** in control flow. Direction: define the result as a capture valid at a checked instant, or revalidate epoch/liveness and share membership after reading; neither can revoke already copied bytes.

6. **Minor — refusal is lexical plus best-effort resolution, not a general secret boundary.** `contract.py:45–67`; `publisher.py:197, 250–256`. Existing symlinks resolving into the exact case-sensitive `.majkee`/`.hlm` components or `.env` basename are refused, including normal save-as when the check runs; untitled buffers are allowed. `realpath` defaults to non-strict resolution and exceptions are ignored, relative names resolve against the plugin process cwd, and different-case names or hard links to protected content are not identified. A symlink target may change after the check. These are limits of this path rule, not proof Sublime itself supplies relative or unresolvable paths. **Observed** in code; nonstandard editor path behavior **inferred**. Direction: specify exact-case and resolution limits and fail closed where path identity cannot be established.

7. **Minor — `current` and index have intermediate states.** `contract.py:377–385, 388–398`. On addition of a second share, index is replaced before `current` is removed; on removal index is replaced before `current` switches. A reader can temporarily see `current` despite two shares, or see a share absent from index while still accessible via its old path. **Observed** from ordered separate writes. Direction: define and validate a coherent manifest/commit point rather than promise simultaneous updates.

8. **Minor — encoding can silently alter text.** `contract.py:359–364`; `publisher.py:63–67`. UTF-8 encoding uses `errors='replace'`; if Sublime supplies an unpaired surrogate, published bytes differ from captured text without an error or flag, while published_chars counts input characters. The cap is in Sublime points and is explicitly flagged for ordinary truncation. **Observed** in code; whether the real editor yields such strings is **unverified**. Direction: report encoding replacement or reject unencodable captures.

9. **Minor — install ownership and interruption claims are stronger than guards.** `install-pkgs/sublime-observer.md:100–109, 127–151, 232–249, 290–293`. A pre-existing unrelated package containing only the five permitted names passes the ownership check and can be overwritten or deleted; a kill or power loss can leave staging despite the claim that any failure cleans it. The manual runtime `rm -r` is guarded by prose, not by verifying ownership or a live publisher. Updates can be partial and the task already admits that. **Observed** in shell and task wording. Direction: verify installation identity and document interrupted/racing operations accurately.

10. **Note — runtime directory safety is conditional on same-user trust.** `contract.py:72–116, 121–135, 169–191`. Default private base and root modes block other ordinary users, and final directory symlinks are rejected at initial checks; no directory descriptors pin ancestors or revalidate them before later path operations. A same-user process can replace directories, pre-create a 0700 root with no publisher, or race checks; startup removes contract-named content in such a root. If the root disappears while running, writes fail and are logged, with no automatic recovery; the marker may remain until unshare/stop. **Observed** in code; exploitation depends on same-user interference. Direction: state this boundary and use pinned directory handles/ownership if stronger protection is required.

11. **Note — editor effects and responsiveness remain bounded evidence, not proof.** `publisher.py:55–94, 181–205, 222–239, 289–305`; `tests/test_static.py:12–19, 43–47`. Captures read up to 200,000 characters and up to 256 selections on the main thread, plus realpath and view metadata; cost depends on buffer and filesystem. `set_status`/`erase_status` intentionally change the status marker; no direct focus, selection, scroll or buffer mutation appears in the traced calls. Some event/command calls outside the capture try block can raise, and the AST denylist misses dynamic `getattr`, aliases, unlisted mutators and indirect calls. The witness records limited synthetic scenarios, not all focus/scroll or large-buffer latency. **Observed** in code and cited witness; performance implication **inferred**. Direction: measure representative worst cases and keep the static check as a narrow regression guard.

## Trace and test coverage

Never-shared event handlers inspect only view ID and return; capture reads the stored shared view, not the event's view. Shares are keyed by view ID and hold the original view object, so a clone is not automatically shared, and a move follows the stored view if Sublime preserves that object and ID. Close and invalid-view polling enqueue removal; reload/revert and save trigger debounced recapture. An ID reused before old close processing could route an event or toggle to the old share; validity and actual Sublime ID reuse semantics are not established here. Index includes metadata only from submitted captures; `current` is based on store shares, with intermediate and queue delays above. A change of text revision writes text before state, keeps current and previous, and removes older versions; readers must retry missing text. No fsync is used: rename atomicity does not imply durability after power loss. A single writer orders its queue, but the queue is unbounded and heartbeat and removal wait behind it; capture freshness is not heartbeat freshness. Shutdown discards queued work and waits for the running writer under the store lock. Unreadable publisher metadata correctly refuses startup rather than cleaning it. Wall-clock jumps and an already-read fresh heartbeat weaken elapsed-time interpretations.

Three highest-value missing tests: (1) deterministic stale-owner resumption and simultaneous-start interleavings, checking all subsequent writes and epoch fencing; (2) `current` switch between state and text with equal revision filenames and distinct bodies; (3) queued publish followed by unshare with injected removal/write failures, checking no fresh-current disclosure after acknowledged revocation. Existing concurrent reader test uses one fixed share and monotonically increasing revisions; sequential second-publisher and synchronous fake-writer tests cannot establish these properties. Add hard-link install tests in isolated temporary directories, and clone/move/reused-ID and sealed save-as timing tests where editor semantics can be witnessed. Existing tests cover standard symlink refusal, cap, revisions, single-share retry, cleanup and basic no-reach paths, but not these races.

**Opinion: not sound** for the stated gate until the concurrency and revocation conditions are resolved or explicitly accepted at the appropriate boundary; this audit does not decide the gate.
