1. **Read back, then ask.** Through the exec desk the lead reads back to Majkee which rows he selects, which bed owns each U-case,
   the stop conditions and where the evidence goes (handoff §8). Then one sheet asks for the release lines of the first run —

   VERDICT.
4. **Observation B** — tmux paste, then Enter as its own step, lead → sample-codex, once. Needs line 5, which names it as one
   explicit exception. Each phase is recorded on its own. An uncertain result is recorded UNCERTAIN; nothing is retried and no
   sender or carrier is switched.
5. **Only what Majkee adds.** A deferred row (handoff §3, the table with the decision each row would inform) or the U01 capture
   (handoff §4). For U01, whether a classification runs is decided **before** the capture.
6. **The packet.** One row per released line, with NOT RUN, UNCERTAIN and MISSING as valid rows. Oraculum reads it once. One sheet
   takes it to Majkee for GO or STOP. The samples are closed by the hand that started them; what happens to their session
   records is his line 7 (and 16).

`/home/hruzam/unikuklatrix/nablarva/.dev/session/relay-X1-probes/raw/runbook-input.spawning-and-seats.trajectory.2026-11-22.md`.

1. Across vendors: main to main, by POINT file and one labelled line. Each main spawns its own children; the POINT names the child
   type, the task, the paths it reads and owns, and what the parent does if the child cannot start.

7. His decisions: one sheet, the desk, at once; one question per turn; his own line quoted; say why it is asked now.
8. In a POINT's gates line, say what is allowed, not only what is forbidden. At every closing commit, sweep the files that state facts.
