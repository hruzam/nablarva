# s01 — Claude Code status line stdin, by documentation (2026-11-26)

Primary source (live-fetched today, H confidence): https://code.claude.com/docs/en/statusline (no page date; the docs track the current release, changelog top = 2.1.332, 2026-11-25).

## 1. Fields on stdin (all documented)
Top level: `cwd`, `session_id`, `session_name`, `prompt_id`, `transcript_path`, `version`, `exceeds_200k_tokens`, `fast_mode`. Objects: `model{id,display_name}`, `workspace{current_dir,project_dir,added_dirs,git_worktree,repo{host,owner,name}}`, `output_style.name`, `cost{total_cost_usd,total_duration_ms,total_api_duration_ms,total_lines_added,total_lines_removed}`, `context_window{total_input_tokens,total_output_tokens,context_window_size,used_percentage,remaining_percentage,current_usage{input_tokens,output_tokens,cache_creation_input_tokens,cache_read_input_tokens}}`, `effort.level`, `thinking.enabled`, `rate_limits{five_hour|seven_day|spend_limit{used_percentage,resets_at,...}}`, `prompt_cache{warm,expires_at,ttl,hit_ratio,...}`, `vim.mode`, `agent.name`, `pr{number,url,review_state,kind}`, `worktree{name,path,branch,original_cwd,original_branch}`.
Optional/absent: session_name, prompt_id, effort, vim, agent, pr, worktree, rate_limits (subscribers only, after first API response), prompt_cache; `used_percentage`/`remaining_percentage` "may be null early in the session".

## 2. Your seven + clock/timers
Model, effort, cwd, context used/left, session name, id, transcript path: ALL documented (table). Effort is the session-set level, "not one that a skill, a subagent, or ultrathink set"; absent if model lacks effort.
Clock/timers: no wall-clock "now" field is documented. Usable: `cost.total_duration_ms` (session running time; excludes time not running), `cost.total_api_duration_ms`, `rate_limits.*.resets_at` and `prompt_cache.expires_at` (epoch seconds; a countdown needs the script's own `date +%s`), `prompt_cache.last_miss_at`. A clock therefore needs `refreshInterval` plus the script's own time call.
Alerts: no alert primitive in the status line; only thresholds you compute (the doc's example colours the bar green <70, yellow 70-89, red 90+).

## 3. When it runs
"Your script runs once when a session starts, including when you resume one." Then on: new assistant message; `/compact` finishes; permission mode change; vim mode toggle; `command` changed; `refreshInterval` timer; a rate-limit `resets_at` reached; a warm prompt-cache `expires_at` reached. "Claude Code debounces updates at 300ms"; a new trigger "cancels the in-flight script". Output shows only after exit code 0; non-zero or empty = blank line. Idle session: "event-driven triggers can go quiet", so fields can be stale; `refreshInterval` (min 1 s, optional, unset = events only) fixes time-based segments only. Context numbers come from "the most recent API response", so they lag until the next response (`/context` can read higher).

## 4. Output
- Multiline: "Multiple lines: each echo or print statement displays as a separate row." No maximum line count documented (not documented).
- Width: "To keep a line from being cut off with …, make it at least four columns narrower than the terminal." So over-wide = cut with an ellipsis (implied); the Tips section also says "long output may get truncated or wrap awkwardly". Wrap-vs-cut is not stated definitively; padding behaviour not documented. `COLUMNS` and `LINES` env vars are passed to the script and refreshed each run; `stty size` "can fail". Emoji count as two columns. `padding` setting adds extra horizontal spacing.
- Colour: "use ANSI escape codes ... (terminal must support them)". OSC 8 links supported. Caveat: "Multi-line status lines with escape codes are more prone to rendering issues".
- Notifications share the row outside fullscreen rendering and move to a row below when they do not fit.
