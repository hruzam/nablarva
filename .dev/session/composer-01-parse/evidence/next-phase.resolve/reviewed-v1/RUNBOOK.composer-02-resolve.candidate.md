## Proposed two-reader contract — approve before implementation

The caller supplies one explicit configuration and an ordered selection list
through a separate API/CLI input, never through packet/body scanning. Configuration
is invocation data, not an installed registry. Use source IDs, reader kinds,
absolute read roots and exact root-relative selections; no cwd, home, environment,
roster or nearest-file discovery. Duplicate IDs/ambiguous keys, unknown source/kind/
selection and repeated selections hold without fallback. Source locations may change
by an explicit invocation; returned provenance records the actual chosen root.

| reader | concrete first example | selected result |
|---|---|---|
| Personal controller-table specimen | `/home/hruzam/reposoma/.majkee/.germline/programs/journal-continuity/CONTROLLER.md`, selecting `list-pending` | Whole controller bytes plus only its selected `fn/list-pending.md`, as separate ordered parts. |
| Whole-file SPECIAL collection | Caller-owned temporary UTF-8 files with explicit relative keys; no standing SPECIAL directory is assumed | Exact selected file bytes, including mixed EOL, controls and absent final LF. No file content becomes a lookup instruction. |

Recommend the narrow specimen profile, not arbitrary Markdown/YAML: exactly the
existing five Functions-table columns, unique function IDs and root-relative file
bindings; reject unsupported/escaped/nested table shapes. Leading flat frontmatter
allows program/stamp and optional revision/scope on the controller; program/function/
stamp and optional revision on the function. Require unique literal scalar keys,
matching program/function and an eight-lowercase-hex stamp equal to the table's
expected stamp. LF or CRLF source lines may be recognized without rewriting bytes.
Freeze this profile and diagnostic cases in the future POINT. It is a local trial
reader; G06 U3/global formats and exceptional composition policies are still pending.

For both readers, recommend mandatory caller expected SHA256 pins for every file
that will be returned, including the controller and selected function. Function
expected **stamp comes from its table**, not caller memory. Missing pins, absent
files, stale hashes/stamps or changed-during-read files hold the whole request with
no usable prepared prefix and no automatic pin update. Stamps/hashes establish
content agreement only, never actor identity, capability, reading by an agent or
activation. SPECIAL needs no invented stamp; preserve an existing declaration only
as source metadata, without imposing germline's unsettled stamp scope on it.

Recommend regular files beneath explicit read roots only: reject absolute member
paths, `..`, symlinks in roots/routes/files, directories and special files. Validate
the route actually opened, using descriptor-based no-follow reads where supported;
no check-then-open escape. An unsupported host holds rather than weakening this
policy. No recursive content links, unselected function reads or network sources.

The result is an ordered collection of exact UTF-8 byte parts plus source ID/kind,
root and selected relative path, observed SHA256, declared revision/stamp when
present, expected-vs-observed comparison and authority-tier label. A label records
provenance; it grants nothing. All selections succeed or no parts are usable.
Output ordering follows explicit selection order and has no clock/random fields.
Keep parts separate: no template expansion, prompt rendering, body insertion,
packet writer or newline repair. An absent final LF remains visible; Phase 0's
body representability limit is not repaired silently.

Propose an importable byte-parts API and a standalone isolated `python3 -I -S -B`
CLI taking explicit configuration/selection JSON from a named operand or stdin.
CLI output must be deterministic ASCII-escaped JSON, including prepared text as
escaped data, with distinct safe validation/operational failures and no raw control
output. Freeze exact schema/status/goldens before code; no packet-header extension.
The common result must serve both kinds without consumers parsing their formats.
An unknown vendor/roster kind is rejected; a later reviewed reader can implement
the same input/result boundary without changing selection or packet parsing.

  stderr/status, failing input/output including buffered failure, environment
  isolation, and source-only operation without shell/editor/session/dashboard.
- Fresh verifier reproduces the real interface and independently derives edge cases;
  it also checks Cartan's source/gavel/scope/STATUS claims. Author tests alone do not
  close the gate. Preserve failure -> bounded correction -> fresh recheck edges.

  recommend office 30 fresh full CLI calls per case, p95 = sorted index 28;

  fixture generation precedes timing. These are proposed finite budgets for gavel,
  not parser timings or grammar/file-size caps. Record all samples/host/runtime;
  a failure holds, other hosts remain unmeasured.
