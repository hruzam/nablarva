## Python — proposed measurable acceptance, not measured results

Proposed reference host: office. Use the actual check CLI, including fresh process
and Python interpreter startup, input file I/O, validation and collected output.
Fixture preparation is outside the clock. Thirty fresh invocations per input,
all successful; keep all timings, host/Python version, exact commands, complete
input byte lengths and fixture hashes. Do not amortize startup with a persistent
process. p95 means the nearest-rank 29th sorted value of 30 samples.

| Input | Proposed acceptance |
|---|---|
| Valid document containing the four exact frozen corpus bodies (38,799 body bytes plus framing/header/outside bytes, total recorded separately) | p95 wall time ≤100 ms |
| Valid document with a 1 MiB body | p95 wall time ≤500 ms |
| Valid document with a 4 MiB body | p95 wall time ≤2 s; median ≤5× the 1 MiB median |

Report the measured growth; these finite thresholds check responsiveness and a
bounded scaling sample, not a proof of asymptotic complexity. Keep the normal
byte-preservation/negative/non-execution suite separate: speed cannot compensate
for incorrect parsing. A missed threshold means the conditional Python acceptance
is unmet and returns to the head; do not redefine the budget after seeing results.
These numbers are a proposed acceptance contract, not a grammar body-size cap.
Cross-host performance remains unverified until measured on the other host.
