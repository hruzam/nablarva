# Wave contrast addendum — architecture child, return pass

## 0. Verdict

**GO with bends. No redesign.**

The three-file child is structurally sound.

Symmetry improved several parts of Wave's first proposal by re-forging the architecture function into Nablarva's existing substrate rather than importing a parallel generic framework:

- one session universe remains;
- cSharp keeps lifecycle and the closure pen;
- Majkee keeps the gavel;
- Houston becomes the grounding / whole-animal coherence seat;
- Oraculum keeps divergence and move formation;
- one architect identity uses bounded cards rather than multiplying personas;
- architecture work remains session work;
- durable architecture remains project truth, not session truth;
- `PROJECT.yaml` stays a skeleton;
- `PROJECT-DESIGN.md` becomes a thin wrapper / animal index;
- organ bodies hold local detail;
- `docs/ARCHITECTURE.md` is the natural candidate for cross-organ / whole-animal architecture;
- `said:`, `inferred:` and `locked:` remain epistemically separate;
- implementation, verification, architecture and canon stay distinct gates.

The bends below refine authority and failure behavior. They do not change the topology.

# 1. Contrast signature — `architecture-process`

## P1 — BEND

Current idea:

> The gap is the missing whole-animal overview and an owner for its upkeep. Design authority already works.

### Bend

The missing function is broader than overview upkeep.

**Whole-animal coherence across independently successful sessions is the job.  
The maintained overview is the instrument of that job.**

Suggested wording:

```md
P1 | The gap is whole-animal coherence across sessions and an owner for checking it.
     The maintained overview is the instrument of that job, not the job itself.
     Local design authority already works.
```

Why:

A documentation keeper can keep pointers fresh and still miss semantic drift. Houston exists because:

```text
intent
  ≈
architecture
  ≈
RUNBOOK
  ≈
implementation
  ≈
documentation
```

A broken `≈` is the architectural finding.

## P2 — HOLD

Majkee remains the moving gavel.

No central architecture seat should absorb operator sovereignty merely because it reasons well.

## P3 — HOLD

Architecture work is session work.

A design sitting is an ordinary session with a different kind of work, not a second process universe.

## P4 — HOLD, with the H2 qualification below

The split is useful:

```text
Oraculum  → diverge / form the move
Houston   → ground / close against the animal
```

Do not merge the two seats.

## P5 — HOLD

The closure pen remains with the head.

Houston may propose or inspect; cSharp remains lifecycle / integration owner.

## P6 — HOLD

Locks keep one durable home and only Majkee's GO creates the lock.

Houston may draft or identify a required lock; he does not self-promote it.

## P7 — BEND STRONGLY

Current form:

> Nothing is mandatory until a count earns it.

Keep the anti-bureaucracy intention, but split **intrinsic gates** from **empirically earned ceremony**.

### Intrinsic gates

Some checks are mandatory because of consequence, irreversibility or authority class, even on the first occurrence.

Candidates:

- new or reopened lock;
- Houston verdict `breaks`;
- architecture designed by Houston that is about to become durable;
- irreversible or hard-to-rollback migration;
- trust/security boundary change;
- fundamental state-ownership change;
- another change explicitly classified by the project as consequential.

### Empirically earned gates

These become mandatory only when repeated evidence justifies the ceremony:

- architecture check on every ordinary closure;
- lint / mechanical checker;
- `PROJECT.yaml` trigger machinery;
- machine-readable envelopes;
- scheduled or generalized audit cadence;
- other process automation.

Suggested replacement:

```md
P7 | No routine ceremony becomes universal without evidence.
     Consequential moves may carry an intrinsic gate from their authority,
     reversibility or risk class before any historical count exists.
```

This preserves the project's measurement-first law without allowing the first serious architectural miss merely because no prior count exists.

## P8 — BEND

Current form:

> No loops. Every check is a straight read that returns a finding.

The correct prohibition is **autonomous recursion**, not explicit re-checking.

Suggested wording:

```md
P8 | No autonomous loops. Every invocation is bounded:
     read → finding → return.
     A correction may trigger a new explicit invocation, preferably fresh-eyed
     when the finding was consequential.
```

Desired shape:

```text
Houston
   ↓
BREAKS
   ↓
return

head / Majkee changes the design

   ↓ explicit new invocation

fresh Houston
   ↓
FITS
   ↓
return
```

No self-propelling Houston↔head conversation is created.

## K7 — HOLD WITH INTERPRETIVE BEND

Current idea:

> Doc claims are testable. Grep before you trust.

Apply this according to claim type.

```text
mechanical claim
    → test mechanically
      file exists
      pointer resolves
      symbol exists
      referenced script exists

architectural claim
    → cite evidence / lock / implementation boundary
      grep may contribute, but cannot prove the whole claim

unknown
    → mark unknown
```

Examples:

```text
"src/foo.php exists"
    → grep / test -f

"engine owns durable state"
    → code + lock + architecture evidence, possibly runtime evidence

"this organ no longer exists"
    → repository evidence + relevant lock / migration evidence
```

Do not turn architecture into grep compliance.

## K8 — HOLD

Upgrade only when measurement indicts the current tier.
