# Architecture contract — whole-animal coherence, documentation, and Houston

## 0. Status

This is the converged contract produced by blind triangulation, challenge, contrast, and return pass between Majkee, Symmetry, and Wave.

The topology is closed.

Majkee has accepted the bends in conversation. Under Nablarva governance, the agreement becomes a durable lock only when the L16 payload below lands in `flag.md`.

No further architecture loop is required unless Majkee explicitly reopens one.

# 1. Missing function

The project does not lack local design intelligence.

The missing function is:

> **whole-animal coherence across independently successful sessions.**

A session can be locally correct and still bend or break the application as a whole.

The maintained architectural overview is therefore **an instrument of the coherence job, not the job itself**.

Houston exists to ask:

> **Does this move still fit the animal?**

The architecture function watches:

```text
intent
  ≈
architecture
  ≈
RUNBOOK
  ≈
implementation
  ≈
documentation
```

A broken `≈` is an architecture finding.

# 3. Divergence and grounding

```text
Oraculum
    opens the possibility space
    forms the question
    challenges the premise

Houston
    grounds the move against the animal
    checks coherence
    closes against architecture, locks, implementation, and docs
```

Houston **does not own divergence**.

If grounding shows that none of the presented options can preserve coherence, Houston may:

1. name the defect in the frame;
2. state the constraints that any viable answer must satisfy;
3. return the hole.

Houston does **not** design the missing alternative inside a normal consult.

The hole goes back to:

- Oraculum, for renewed divergence; or
- a Houston architectural sitting.

# 4. One session universe

Architecture work is session work.

There is no parallel architecture-session lifecycle.

Do not create:

```text
.dev/session/
.dev/architecture-session/
```

as competing process universes.

Temporary architecture work stays in the ordinary session substrate.

Durable architecture is promoted into durable project documentation.

A Houston sitting is:

> **an ordinary session with one session gate.**

# 5. One gate, several checks

In Nablarva vocabulary, **gate** means:

> the single closing condition of one session.

A session gate may require several independent **checks**.

| check | question | conditionality |
|---|---|---|
| **implementation** | Was the assigned work built? | according to session work |
| **verification** | Does it meet acceptance? | according to session gate |
| **architecture** | Does it preserve the intended system shape? | intrinsic or empirically earned |
| **canon** | Does Majkee accept this as durable truth? | only when closure promotes gaveled canon |

```text
SESSION GATE
    │
    ├── implementation check
    ├── verification check
    ├── architecture check      [when applicable]
    └── canon check             [when promotion requires GO]
```

Never collapse these checks into one undifferentiated `PASS`.

# 6. Intrinsic checks versus earned ceremony

## 6.1 Intrinsic architecture classes

Some architecture checks are required from first occurrence because of consequence, reversibility, or authority class.

Initial intrinsic classes:

- **lock** — new or reopened architectural lock;
- **irreversible** — costly/unsafe rollback;
- **trust** — trust or security boundary change;
- **ownership** — fundamental state/responsibility ownership change;
- **architect-authored consequential design** — the architecture seat materially designed what is now being accepted;
- **`breaks`** — any Houston `breaks` verdict is intrinsic on occurrence.

At RUNBOOK authoring:

```text
known intrinsic class
    → RUNBOOK known constraints
```

If discovered later:

```text
intrinsic class found mid-session
    → STATUS holds:
```

If the head misses a consequential class, the missed classification is a **process finding**, wherever first discovered.

New permanent classes require:

```text
proposal
    ↓
Majkee GO
    ↓
flag line
```

## 6.2 Earned mechanisms

Routine machinery is added only after evidence earns it.

Candidates:

- mandatory architecture check on ordinary closures;
- lint / pointer checker;
- `PROJECT.yaml` trigger machinery;
- machine-readable Houston envelopes;
- generalized audit cadence;
- other process automation.

Principle:

> **No routine ceremony becomes universal without evidence.  
> Consequential moves may carry an intrinsic check before any historical count exists.**

# 9. Houston card 1 — consult: in-session grounding check

## Spawned by

- session head;
- Majkee directly.

## Fires when

A move:

- hits an architecture trigger class;
- crosses an organ boundary;
- touches a lock;
- develops architecture drift;
- needs an architecture check at closure.

Local choices wholly inside one organ remain the head's inline responsibility unless evidence says otherwise.

## Reads

The smallest relevant set:

- RUNBOOK and the move;
- relevant `PROJECT-DESIGN.md` wrapper lines;
- touched organ bodies;
- applicable `docs/ARCHITECTURE.md` sections;
- cited flag locks;
- evidence needed to judge the shape.

## Writes

Nothing.

## Returns

Plain Markdown, normally one page or less:

- verdict;
- at most five constraints;
- findings;
- `said:` and `inferred: houston` kept separate;
- commit-pinned cites where needed.

Constraints land in existing state slots:

```text
known before execution
    → RUNBOOK known constraints

discovered during execution
    → STATUS holds:
```

## Verdicts

| verdict | meaning | result |
|---|---|---|
| `fits` | consistent with wrapper, bodies, whole-animal architecture and locks | proceed |
| `stretches` | coherent but bends a named line | proceed with named constraint/hold |
| `breaks` | contradicts a lock or contract | stop that path; fresh eyes; Majkee resolves reopening |
| `unclear` | project truth does not answer | finding: the shelf has a hole |

## Missing alternative

Houston may return:

```text
frame defect:
    what is missing / wrongly constrained

required properties:
    constraints any viable alternative must satisfy
```

Houston does **not** draft the replacement design inside consult.

# 10. Houston card 2 — audit: the whole animal

## Spawned by

Majkee, ad hoc.

No default cadence.

Typical reasons:

- before a sitting;
- after meaningful closures;
- when the animal smells wrong;
- suspicious wrapper staleness;
- suspected cross-organ drift.

## Walk

```text
PROJECT-DESIGN wrapper
    ↓
oldest / changed organ bodies
    ↓
docs/ARCHITECTURE.md
    ↓
relevant guides and collateral docs
    ↓
flag locks against implementation reality
```

## Checks

- pointers resolve;
- key files exist;
- one home per fact;
- wrapper remains thin;
- mechanical claims are mechanically testable;
- architecture claims are supported by locks/evidence;
- unknowns remain named unknowns;
- coherence chain holds:

```text
intent ≈ architecture ≈ RUNBOOK ≈ implementation ≈ documentation
```

## Claim types

```text
mechanical claim
    → test mechanically

architectural claim
    → cite lock, code boundary, evidence, or runtime observation

unknown
    → state unknown
```

Architecture must not degrade into grep compliance.

## Return tags

- `mech` — scriptable/mechanical mismatch;
- `judge` — architectural reasoning required;
- `cross` — spans organs / whole-animal boundary.

Keep:

```text
verified-wrong
≠
flagged-by-age
```

## Audit pen

Houston may propose/update wrapper mechanics only:

- pointers;
- `checked:` stamps;
- organ one-liners whose meaning has not changed.

Houston does not silently rewrite:

- organ contracts;
- locks;
- project intent;
- implementation truth.

Substantive disagreement returns as a finding.

## Keeper

When the current convergence keeper retires, Houston's audit card becomes keeper of `PROJECT-DESIGN.md`.

# 12. Documentation constitution

Documentation is a map, not a retrieval system.

At Nablarva's current scale, no vector index is justified for dev-time navigation.

## One home per truth class

| surface | role | holds | must not become |
|---|---|---|---|
| `PROJECT.yaml` | machine map | skeleton facts, canonical pointers | prose encyclopedia |
| `PROJECT-DESIGN.md` | thin wrapper / animal index | whole animal in a few lines, organ one-liners, pointers, `checked:` stamps | organ detail / progress register |
| `docs/ARCHITECTURE.md` | whole-animal body | cross-organ architecture, layer model, dependency direction, shared grammars, cross-organ ownership | individual organ detail |
| organ body | local detail | organ contract, key files, decisions in force, trajectory notes | another organ's truth |
| `flag.md` | locks | L-ids, docket, thresholds | descriptive duplicate |
| `pulse.md` | live router | one line per live session | next-action narrative |
| session folder | temporary work | briefs, raw, RUNBOOK, STATUS, evidence | durable project truth |

## `docs/ARCHITECTURE.md` — GO

Canonical navigation:

```text
PROJECT.yaml
    machine skeleton
        ↓
PROJECT-DESIGN.md
    cheap animal silhouette + pointers
        ↓
docs/ARCHITECTURE.md
    cross-organ structure
        ↓
organ bodies
    local detail
```

Wave's earlier `.dev/architecture/` proposal is withdrawn for Nablarva.

# 13. Documentation growth law

1. **Born thin.** New organ: one or two wrapper lines.
2. **Sub-chapter.** Contracts/decisions live in organ body.
3. **Folder.** Large body becomes a folder with a small index.
4. **Archive.** Retired organ moves under archived index with replacement named.

The wrapper stays small however large the animal becomes.

---

# 14. Documentation rules

1. **Map, not encyclopedia.**
2. **One home per fact.**
3. **Durable high-level docs prefer capability/domain words over brittle line-number references.**
4. **Every organ body names key files.**
5. **Declare staleness.**
6. **Age is a candidate, not a finding.**
7. **Test claims by type:** mechanical → mechanically test; architectural → cite evidence/lock; unknown → say unknown.
8. **Born thin, promoted on need.**
9. **Recipes become tools when repeated use earns automation.**
10. **Measure before upgrading documentation machinery.**

Durable docs never cite prunable session paths except by commit pin:

```text
repo@sha:path
```
